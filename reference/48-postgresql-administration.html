查看配置来源，理解 ALTER SYSTEM 与 CHECKPOINT

PostgreSQLCHECKPOINT 的 MODE、FLUSH_UNLOGGED 为 PostgreSQL 19+

逻辑复制通过发布、订阅和槽传递表数据

PostgreSQL

准备两个独立试验实例，两端分别建匹配的表和模式。发布端需要逻辑复制、WAL sender、槽和复制账户的相应配置。订阅通过发布端可认证的练习账户连接，凭据在实例上按需配置。 发布端需数据库 CREATE 与发布表所有权。订阅端用具数据库 CREATE 和 pg_create_subscription 权限的管理员。FOR ALL SEQUENCES 需要超级用户。订阅端需 pg_create_subscription 与当前数据库 CREATE，发布端需 REPLICATION 和初始快照所需 SELECT。非超级用户的订阅连接须显式配置口令，替换为专用凭据。在各自的实例执行指定片段。初始复制为异步过程，先等订阅初始化完成，再按结果表对应 SQL 查询。

用 WAIT FOR LSN 在备用库等 WAL 重放

PostgreSQLPostgreSQL 19+

先在主库提交业务写入，再查询目标 LSN，把真实值粘贴到已连备用库的 psql。WAIT 返回成功后再开始查询。使用 standby_replay 才确认 WAL 已应用，standby_write 和 standby_flush 是不同保障。在各自的实例执行指定片段。
