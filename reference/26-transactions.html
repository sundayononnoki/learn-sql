管理事务处理

事务把一组写入当作业务单元。InnoDB 支持回滚，MyISAM 不提供事务回滚。用 InnoDB 观察回滚、提交、保存点和并发下的行锁。

MySQL

同一次事务写订单和明细。普通语句错误往往只回滚失败语句，遇到错误时由应用明确撤销本次业务单元。

SAVEPOINT 部分撤销

MySQL

保存点标记事务中间的位置。ROLLBACK TO 撤销之后的事务性写入，并保持事务开启。COMMIT 或整个事务回滚会清除保存点。局部回滚后仍可能持锁，可用 RELEASE SAVEPOINT 移除标记。

执行后　第一次更新到 1 并做保存点，再加到 11。回到保存点并提交后持久值为 1。

第一次加 1 提交，第二次加 10 撤销，提交后 n 为 1。

AUTOCOMMIT 和隐式提交

MySQL

默认每条独立语句自动提交。SET SESSION 修改当前连接的默认提交行为。许多普通表 DDL 会隐式提交，事务里先做完 DML 再单独安排 DDL。

执行说明

执行前　n=1，会话最初 autocommit=1。

执行后　关闭自动提交后试写到 10。回滚撤销并打开自动提交，最终输出 1 | 1。

撤销加 9 后得到 1 和 1。若从 0 切回 1 时仍有开放事务，切换本身提交事务。

ACID、隔离级别与一致性读

MySQL

原子性要求整组操作一起生效，一致性依赖约束和业务规则，隔离性控制并发读写可见性，持久性让已提交的事务在故障后可恢复。InnoDB 默认 REPEATABLE READ 的普通读取可复用事务快照。READ COMMITTED 下普通读取每次取得新快照。

执行前　会话默认 REPEATABLE READ，已提交的计数值为 1。

两个连接观察 FOR UPDATE

MySQL

在连接 A、B 分别选择 learn_sql_lab。按 A 锁行 → B 尝试 → A 提交 → B 再试的顺序。锁定读必须在事务中使用。保持事务简短并统一加锁顺序可减少死锁。死锁通常使 InnoDB 回滚被选中的整个事务，可按业务语义重试。锁等待超时默认只回滚失败语句。
