SQL Server · SQL Server 版本与迁移附录

从 2016 到 2025 追踪会改变现有语句的能力。对 2025 逐项核对实际 build、数据库兼容级别、GA 或预览状态。文档核对截至 2026 年 11 月 21 日。

引擎版本、CU、版本类型与兼容级别

SQL Server样例为 SQL Server 2025 CU11（2026-11-12 发布），按 2026-11-21 核对。查询本身可用于较早版本。

先读实例主版本、完整 build、更新分支和版本类型，再读当前库兼容级别。CU 的具体功能需要对照发布说明。2025 的 RTM build 是 17.0.1000.7，CU11 是 17.0.5065.9。

2017：STRING_AGG 与兼容级别

SQL ServerSQL Server 2017+；STRING_AGG 可在任意兼容级别使用，WITHIN GROUP 需要级别 ≥110。

2017 提供 STRING_AGG、CONCAT_WS、TRIM，并扩展到受支持的 Linux 平台。迁移手写拼接时先核对排序、NULL 和返回类型。

2025：REGEXP 谓词、提取和替换

SQL ServerSQL Server 2025（17.x）。REGEXP_LIKE 和表值 REGEXP_MATCHES、REGEXP_SPLIT_TO_TABLE 需要兼容级别 ≥170。REGEXP_COUNT/INSTR/REPLACE/SUBSTR 等其他标量函数可用较低级别。

用 REGEXP_LIKE 判断是否匹配，用 REGEXP_SUBSTR 取片段，REGEXP_REPLACE 做替换。用 CASE 把谓词变为可显示的 0/1。该实现使用 RE2 语义，不应直接搬用 MySQL ICU 模式。

查看执行前的数据

SELECT CASE WHEN REGEXP_LIKE('A-123', '^[A-Z]-[0-9]{3}$') THEN 1 ELSE 0 END AS accepted, REGEXP_SUBSTR('A-123', '[0-9]+') AS digits, REGEXP_REPLACE('A-123', '[0-9]+', '[id]') AS masked;预期结果
accepteddigitsmasked

匹配区分大小写与模式标志有关。RE2 语法对某些 ICU 功能和复杂正则的行为不同，迁移时用正反样例核对。
